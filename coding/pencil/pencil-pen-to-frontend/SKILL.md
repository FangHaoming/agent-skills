# Pencil `.pen` To Frontend

## 核心目标

把 `.pen` 当作“组件树和布局骨架输入”，而不是直接当成最终业务代码来源。

默认目标是先做语义化映射，再产出代码方案，最后才进入实现。

## 默认工作流

1. 先判断输入是否可直接用于生成
2. 提取目标页面或目标 `frame`，不要一次处理整个大文件
3. 先输出“设计节点 -> 项目组件”映射
4. 再输出组件拆分、数据流、交互假设和文件结构
5. 用户确认后，再生成最终代码

## 关键约束

### 1. 先语义化，再生成代码

- 优先读取并保留节点的 `name`、层级、`context`、文本内容、图标名
- 如果设计输入只有视觉结果，没有语义命名，先指出风险，再补做结构化整理
- 不要直接把视觉层级翻译成大量匿名 `div`

### 2. 布局优先，不依赖绝对定位

- 优先依据 `layout`、`gap`、`padding`、`alignItems`、`justifyContent`
- 弱化 `x`、`y`、`top`、`left` 等纯坐标信息
- 如果设计主要依赖绝对定位，先转译成容器布局，再生成代码

### 3. 先映射现有组件体系

- 先判断哪些节点对应现有组件，哪些只是容器，哪些才需要新增组件
- 优先复用项目已有 `Button`、`Table`、`Form`、`Layout`、`Empty`、`Pagination` 等组件
- 不要绕开现有组件体系直接生成完整页面

### 4. 大页面必须拆块

默认按页面区域拆分，例如：

- `Header`
- `Sidebar`
- `FilterBar`
- `TableArea`
- `Modal`

先逐块分析，再组装页面。

### 5. 输出约束要先说清

在生成代码前，优先补齐这些约束：

- 技术栈，如 `React + TypeScript`
- 样式方案，如 `CSS Modules`、`Tailwind`、`less`
- 组件库，如 `Ant Design` 或内部组件
- 路由、请求、状态管理约定
- 文件落点，如页面、子组件、hooks、types 的目录
- 是否允许新建基础组件

### 6. 样式优先映射 token

- 优先复用现有 design token 或项目变量
- 没有 token 再退回具体值
- 不要凭空发明新的 token 名称
- 不要在代码中散落硬编码颜色、字号和间距

### 7. 先出分析，后出代码

默认分两步：

1. 输出组件映射、拆分方案、数据流、交互假设
2. 用户确认后再生成代码

## 推荐输入裁剪

不要直接读取整个大型 `.pen` 文件。优先抽取目标页面的子树，并重点保留：

- `type`
- `name`
- `context`
- `layout`
- `gap`
- `padding`
- `alignItems`
- `justifyContent`
- `fill`
- `stroke`
- `cornerRadius`
- 文本内容
- 图标名

可弱化或移除：

- 纯坐标信息
- 与布局无关的噪声字段
- 不重要的装饰节点

## 建议输出格式

先输出以下内容，不要一开始直接写代码：

1. 目标页面理解
2. 设计节点到项目组件的映射表
3. 组件拆分方案
4. 数据流和交互假设
5. 文件结构建议
6. 风险与待确认项

确认后，再生成最终代码。

## 生成代码时必须检查

- 是否重复封装已有组件
- 是否绕开现有组件体系
- 是否把设计稿文本不当地写死
- 是否缺少 `loading / empty / error` 态
- 是否考虑滚动区域与响应式
- 是否把展示逻辑和交互逻辑拆开
