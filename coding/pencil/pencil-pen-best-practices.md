# Pencil `.pen` 转前端代码最佳实践

`Pencil` 的定位就是“Design on canvas. Land in code”[官网](https://www.pencil.dev/)。对前端来说，让 AI 根据 `.pen` 生成代码的最佳实践，不是把整个文件一股脑丢给模型，而是先把 `.pen` 变成“可映射到项目组件体系的语义输入”。

## 核心原则

### 1. 先做语义化设计，再做代码生成

如果 `.pen` 里只有视觉信息，AI 很容易生成一堆 `div`；如果有明确的节点命名、层级和上下文，AI 才能稳定映射到业务组件。

当前 `PixMax-console.pen` 已经有不错的基础，例如：

- `子账号管理页`
- `顶部栏`
- `侧边导航-展开`
- `menu_sub`
- `context`

这类信息对 AI 生成可维护代码非常有价值。

### 2. 优先使用布局语义，不要依赖绝对定位

对 AI 最友好的设计输入是：

- `layout`
- `gap`
- `padding`
- `alignItems`
- `justifyContent`

而不是：

- `x`
- `y`
- `top`
- `left`

`.pen` 比纯截图或纯 Figma CSS 更适合生成前端代码，原因就在这里。

### 3. 先映射到现有组件库，再生成页面

如果项目已经有 `Button`、`Table`、`Form`、`Layout`、`RemoteSelect`、`Empty`、`Pagination` 等组件，应该先让 AI 判断：

- 哪些设计节点对应现有组件
- 哪些只是容器
- 哪些需要新建组件

不要一上来就让 AI “直接生成完整页面”，否则很容易绕过现有组件体系。

### 4. 大页面拆块生成，不要一次生成整个 `.pen`

像 `PixMax-console.pen` 这种两万多行的大文件，最稳的方式是：

1. 先只提取目标 `frame`
2. 再拆成 `Header`、`Sidebar`、`FilterBar`、`TableArea`、`Modal`
3. 逐块生成
4. 最后再让 AI 组装页面

这样生成质量和可维护性都会更高。

### 5. 明确输出约束，比设计稿本身更重要

给 AI 的约束至少要包括：

- 技术栈：`React + TypeScript`
- 样式方案：`CSS Modules` / `Tailwind` / `styled-components` / `less`
- 组件库：`Ant Design` 或内部组件
- 路由、请求、状态管理约定
- 文件落点：页面、子组件、hooks、types 分别放哪里
- 是否允许新建基础组件

### 6. 颜色、间距、字号优先映射 token

最佳做法不是让 AI 在代码里到处散落 `#1677FF`、`12px`、`8px`，而是要求它：

- 优先复用现有 design token
- 没有 token 再退回具体值
- 不要凭空发明新的 token 名称

### 7. 先产出映射分析，再产出代码

推荐拆成两步：

1. 先输出组件映射、拆分方案、数据流和交互假设
2. 确认后再生成代码

这比一步到位稳定很多。

## 推荐工作流

### 1. 预处理 `.pen`

不要直接喂原始大文件，先抽出当前页面的核心结构，重点保留：

- `type`
- `name`
- `context`
- `layout`
- `gap`
- `padding`
- `alignItems`
- `justifyContent`
- `fill`
- `stroke`
- `cornerRadius`
- 文本内容
- 图标名

弱化或移除：

- 纯坐标信息
- 与布局无关的噪声字段
- 不重要的装饰节点

### 2. 让 AI 先做“设计节点 -> 项目组件”映射

例如：

- `顶部栏` -> `PageHeader`
- `侧边导航-展开` -> `SideNav`
- `menu_sub` -> `NavItem`
- 筛选区 -> `Form + RemoteSelect + Button`
- 表格区 -> `Table + Empty / Pagination`

### 3. 先生成页面骨架

先让 AI 输出：

- 页面组件结构
- 子组件拆分
- mock 数据接口
- props 设计

### 4. 再生成可落地代码

要求 AI：

- 优先复用现有组件
- 不要发明新的基础样式体系
- 样式只做必要补足
- 交互逻辑和展示逻辑分离

### 5. 最后做一次对照审查

让 AI 检查：

- 是否有重复封装
- 是否绕开了现有组件
- 是否把设计稿中的展示文本写死
- 是否缺少 `loading` / `empty` / `error` 态
- 是否考虑响应式和滚动区域

## 推荐提示词模板

```text
你是资深前端工程师。请根据我提供的 .pen 页面结构生成前端代码，但必须遵守以下规则：

1. 技术栈：React + TypeScript
2. 优先复用我项目现有组件，不要无意义新造轮子
3. 先输出“设计节点到项目组件的映射表”和“组件拆分方案”，不要直接写代码
4. 布局优先依据 layout / gap / padding / alignItems / justifyContent，不要依赖绝对定位
5. 样式优先复用设计 token 或项目变量，不要散落硬编码颜色和尺寸
6. 对于不明确的交互，先列出假设
7. 输出文件结构、组件职责、props 设计、数据流
8. 我确认后，再生成最终代码

这是项目已有组件/页面示例：
[贴项目现有组件、页面代码]

这是目标 .pen 中的目标 frame：
[贴当前页面对应的 .pen 子树，而不是整个大文件]
```

## 最关键的一句话

`.pen` 最适合拿来生成“组件树和布局骨架”，不适合单独作为最终业务代码输入。真正稳定的做法是：`.pen` 提供设计结构，项目源码提供组件约束，AI 负责做映射和组装。
