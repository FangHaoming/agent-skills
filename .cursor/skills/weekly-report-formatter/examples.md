```markdown
用户引用目录：

@weekly-reports/

目录下候选文件：
- `第18周周报.md`
- `2026年5月上旬周报.md`
- `周报_0502.md`

当前周报原始输入：

本周完成工作:
已完成：
【前台】用户权益页改版已完成，待提测

进行中：
【账号体系】登录态优化继续联调
```

### 示例 6 处理说明

```markdown
1. AI 先在 `@weekly-reports/` 中识别周报候选文件。
2. 这些文件都像上一份周报，但仅凭当前命名无法稳定判断哪一个才是最新的上一份历史周报。
3. 因为上一份周报尚未唯一确定，AI 此时不能继续整理本周周报，而应先请求用户确认。
```

### 示例 6 正确输出

```markdown
检测到多个可能作为“上一份周报”的候选文件，目前无法唯一确定：

1. `第18周周报.md`
2. `2026年5月上旬周报.md`
3. `周报_0502.md`

请确认本次需要对比的上一份周报是哪一个；确认后我再继续整理本周周报。
```

### 示例 8 处理说明

```markdown
1. AI 先将上一版周报中的 `**进行中**`、`**已完成**`、`后续重点` 和 `下周工作计划` 一起抽取为跨周对照基线。
2. `【sso/个人中心】Instagram 社媒授权` 在当前输入中出现了更接近结果态的描述，因此从上一版“进行中”更新为本周“已完成”。
3. `国内外官网、后管、个人中心 CPU 单价由核时改为线程时需求` 虽然没有在当前输入中再次提到，但它属于上一版 `后续重点` / `下周工作计划` 中仍未闭环的事项，且没有明确关闭信号。
4. 因此该事项不能被补进本周 `本周完成工作`，但必须继续继承到新的 `后续重点` 或 `下周工作计划`，避免跨周整理时漏掉。
```
