# 周报脱敏示例

## 示例 1

### 示例 1 输入

```markdown
本周完成工作:
已上线

1. 【业务线A】某功能优化需求，已于4月20日上线
2. 【项目B】多端能力支持相关需求，已于4月21日上线
3. 【管理后台】配置能力优化需求，已于4月24日上线

已完成

1. 【业务线A】某活动页开发完成（待提测）
2. 【管理后台】某临时需求已完成开发，预计下周测试完成后单独上线。需求变更：去掉某字段必选、增加某字段必选。

进行中

1. 【业务线A】某活动页开发
2. 某账号体系相关需求

风险点

1. 某账号体系相关需求存在延期上线风险，因关键依赖暂未提供；若延期需临时隐藏相关模块
```

### 示例 1 输出

```markdown
本周完成工作:

**已上线**

1. 【业务线A】某功能优化需求，已于4月20日上线
2. 【项目B】多端能力支持相关需求，已于4月21日上线
3. 【管理后台】配置能力优化需求，已于4月24日上线

**已完成**

1. 【业务线A】某活动页开发已完成，待提测
2. 【管理后台】某临时需求已完成开发，预计下周测试完成后单独上线；需求变更为去掉某字段必选、增加某字段必选

**进行中**

1. 【业务线A】某活动页开发进行中
2. 某账号体系相关需求进行中

本周工作总结:

1. 本周已完成多个业务线与后台需求上线交付，覆盖前台能力支持和后台配置能力建设。
2. 已完成部分后续需求开发，为下周提测和单独上线做准备。
3. 当前仍在推进活动页及账号体系相关需求，整体节奏稳定但存在外部依赖风险。

后续重点:

1. 推进管理后台某临时需求测试完成后单独上线。
2. 推进多端统一计费规则调整相关需求。
3. 持续推进活动页和账号体系相关需求。

风险点:

1. 某账号体系相关需求存在延期上线风险，因关键依赖暂未提供，若延期需临时隐藏相关模块。

下周工作计划:

- 

需协调与帮助:

- 
```
