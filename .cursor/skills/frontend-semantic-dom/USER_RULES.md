前端代码生成时，DOM 必须优先保证语义化、可读性和可维护性。先按内容结构设计语义骨架，再补充布局容器和样式挂载点。优先使用 `main`、`section`、`article`、`header`、`footer`、`nav`、`ul`、`ol`、`li`、`form`、`label`、`fieldset`、`legend`、`button`、`table`、`thead`、`tbody`、`tr`、`th`、`td` 等语义标签；非必要不要使用 `div` 和 `span`。禁止无意义的多层 `div` 嵌套，禁止用 `div` / `span` 模拟交互元素。列表必须使用列表语义，表单必须有正确标签关联，表格数据必须使用表格语义。DOM 层级应尽量扁平，重复结构应优先抽成子组件，类名应体现业务语义或组件职责。输出前先自检：是否存在可替换为语义标签的 `div`、是否有纯样式包裹层、是否有错误交互语义、是否有可抽取的重复结构，以及当前结构是否便于后续维护、测试和局部替换。
